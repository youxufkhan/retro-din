# Contributing

This started as a personal theme, so there's no formal process — issues and
PRs are welcome regardless.

## Before changing an asset

Almost everything under `desktoptheme/`, `icons/RetroDIN-src/`, and
`kvantum/` is generated by a script in `scripts/`, not hand-edited. Check
whether a `gen_*.py` produces the file you're about to touch — if it does,
change the script (usually a spec table or a color constant near the top)
and re-run it, rather than editing the SVG output directly, or your edit
will be silently overwritten by the next `scripts/install.sh` run.

## Verifying a change

- `python3 scripts/render_check.py <file.svg>` — renders a contact sheet
  and reports any element that fails to draw. Use this over ImageMagick's
  `convert`, which has given false negatives on gradients and glyphs that
  Qt renders correctly. Needs `python3-pyqt6.qtsvg` (Debian/Ubuntu) —
  base `PyQt6` doesn't include the SVG bindings on its own.
- `python3 scripts/validate.py svg <file> <element-ids...>` — checks a set
  of element IDs resolve in an SVG.
- After a desktoptheme or icon change, re-run `scripts/install.sh` and
  actually look at the affected UI (panel, task switcher, a menu) — these
  are visual assets; a script passing doesn't mean it looks right.

## Live-testing without disrupting your session

- Splash: `ksplashqml --test --window com.retrodin.theme`
- Lock screen: `/usr/lib/x86_64-linux-gnu/libexec/kscreenlocker_greet --testing`
- SDDM: `sddm-greeter-qt6 --test-mode --theme sddm/RetroDIN`

Never trigger a real lock/login/reboot to test a change.

## Commits

Keep commit messages in the imperative, present-tense style already used in
`git log` (e.g. "Fix pager fallback", not "Fixed" or "Fixes"). One logical
change per commit where practical.
